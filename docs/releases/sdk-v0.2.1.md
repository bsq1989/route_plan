# SDK v0.2.1 圆心覆盖停靠修正版

发版日期：2026-11-08。Git 标签：`sdk-v0.2.1`。SDK 版本 `0.2.1`，仓库规划器版本 `0.3.1`。Python 3.10 以上，运行依赖不变。

v0.2.0 把目标圆与消除区相切也算作停靠覆盖，条件过宽。本版对 `method="stops"` 统一要求：一个批次的每个原始目标圆心都位于同一停车位、同一朝向下的消除矩形内。圆边缘相切、部分相交但圆心在外，都不能算覆盖。不要求整个圆进入；圆心在矩形边界上按区域内处理，数值容差沿用几何内核。

重叠目标也逐 ID 检查圆心，不能因为与区域内目标重叠就顺带清除区域外 ID。车身及外扩区的碰撞仍按完整物理半径计算，包括正前方，不把物体当成点处理碰撞。输入协议和参数模板不增加字段。

候选覆盖集合、可行初解、解析进入时刻、显式拾取、SDK 输出及逐帧回放全部使用同一圆心规则。新增记录保存 `pickup_rule="center"`。旧 `feasibility/length` 接触行为保持兼容；旧归档缺少该字段时仍按旧接触规则回放，不能把旧成绩当成新规则验证。

## 重新验证

20 个场景，每组 40 个目标：10 组随机分布、10 组目标簇。A、B 均在圆心条件下重新规划；A 为长度优先基准，预算 3 秒；B 复用 A 初解做停靠优化，总预算 6 秒包含 A 耗时。最终回放额外计时。

| 场景 | A 拾取服务数 | B 拾取服务数 | A 路程 | B 路程 |
| --- | ---: | ---: | ---: | ---: |
| 10 组随机 | 400 | 377 | 439.29 m | 507.68 m |
| 10 组目标簇 | 388 | 100 | 207.93 m | 218.51 m |
| 总计 | 788 | 477 | 647.21 m | 726.18 m |

两组均 20/20 全清、无碰撞，800 个 ID 保留。每个停靠批次独立将所有圆心变换到车体系，逐个验证矩形内条件；两种仿真步长 0.013 秒和 0.7 秒回放通过。停车优化总体减少 39.5% 的拾取服务数，路程增加约 12.2%，符合停车优先的目标顺序；该结果仅适用于本固定测试集和预算。

70 项仿真测试、60 项规划器测试通过，新增覆盖外切、部分相交、重叠成员圆心在外、旋转坐标、完整物理半径碰撞、SDK 合并批次及旧归档兼容。独立 Python 3.10 的 wheel 和源码包各通过 29 项 API/停靠测试；各跳过 1 项按分发约定不携带的 CLI 测试。安装后 SDK 另回放全部 20 组冻结场景并检查所有拾取圆心。

摘要：[圆心覆盖 A/B 记录](../../planner/benchmarks/stops-center-ab-v1.json)。复现：

```bash
python planner/tools/benchmark_stops.py --output sim/output/center-stops-release --render
python planner/tools/package_sdk.py --verify
```

调用仍为 `plan({**request, "method": "stops"})`，按 `pickup_stops[].goal_index` 到达完整目标位姿后处理其 `target_ids`，实际确认后再继续后续动作。SDK 成功仍为模型预测，不能替代实车拾取确认。
