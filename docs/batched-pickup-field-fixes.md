## 1. 用坐标关联目标，支持逐步发现

**第一帧可以缺 tracking ID，也可以只看到一部分物品。** 基础 `plan()` 按当次提交的准确坐标规划。每个目标的 SDK `id` 在请求内唯一，用于把 `pickup_stops` 对回输入。分段观测 `plan_observation_step()` 可以先根据已有粗测坐标和误差半径规划下一次观测。SDK 用同一个 `id` 让精测覆盖对应的粗测，关联由 Gateway 完成。

1. Gateway 在任务内生成自己的目标 ID。保留相机 tracking ID 供关联和日志使用。每帧在采集时刻转换到 `map`，依据坐标、测量误差及定位质量关联到待拾取目标。一对一匹配明确时更新原记录，新的独立物体分配新 ID。
2. 近处观测能否作为精测，由测量范围、质量和坐标变换有效性决定。当前 Gateway 的 `tracked` 条件会阻止无有效 tracking ID 的检测进入精测列表，需要把这个条件从精测判定中移开。tracking ID 提供的关联也要与位置一致。
3. 到拾取位后，在本次计划目标和新帧检测之间重新做位置匹配。确认匹配后，再检查当前机械臂可拾取区。多个候选对应不清时保留占用、暂停该物品的拾取并重测。只在实际拾取成功后移除相应目标。记录 ID 变化、匹配结果和冲突，便于从日志核对。

如果一帧没有可用坐标，Gateway 仍可利用先前可信的记录做下一步规划。尚未观测到的物品需要靠后续观测发现，任务完成状态取决于覆盖确认和实际拾取结果。

## 2. 合并 `init` 和 `observe`，受阻后从实测状态恢复

1. **两种观测写入同一份待拾取列表。** `init` 提供每轮初始观测。`observe` 是机械臂在拾取位的抓前小视野，在筛选本批可拾取目标前，先写入这帧所有坐标有效的检测。记录来源、采集时间、最近可信坐标和误差。批次外目标保留到后续规划，顺序由下一次规划决定。当前批次还有动作时，Gateway 下发下一段前，用更新后的全部未拾取目标重新检查实际路径。检查通过可续走原计划，发现冲突就从实测停车位重规划。
2. **未见到和已拾取分别处理。** 单次空帧、遮挡或 tracking ID 消失，都保留待拾取记录。短时间内仍有效的精测坐标可以跨批保留，有效性由时间、TF 与定位质量、场景是否变化及复测冲突共同判断。坐标失效后保留保守占用并安排复测。若安全检查无法给出可执行的复测动作，返回未完成并保留剩余目标。保留的精测供路线恢复使用，实际抓取仍要求抓前新帧确认目标和可拾取区。
3. **路径被拒后，从实际停车位重新规划。** 保留未拾取目标及有效精测，重新生成短距离接近方案，再对实际下发的路径做完整碰撞与已启用 fence 检查。优先验证底盘能否按 SDK 的原地转向和前向直行模型执行短段。若执行端仍使用 Nav2 路径，按它的真实路径重新验证，路径不安全时保持停车。该实车回放的精测坐标重规划只验证了 SDK 能生成路线，仍须验证底盘执行路径。
4. **结束前复扫盲区。** 待拾取列表为空时，若这次任务范围还有可安全复查的盲区，换视角再取帧。只有待拾取列表为空且已用有效帧确认任务范围的观测覆盖，才报告完成。空检测帧只能确认该帧的有效视野，取帧失败或位姿无效时继续复测。仍有未确认的区域或目标、且无法安全复查时，记录原因并返回未完成。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 初始只看到部分物品，且检测缺失 tracking ID | 对已有可靠坐标能出规划。后续发现的目标进入待拾取列表。 |
| 同一个物品在粗测、精测或抓前换 ID | 位置匹配明确时仍关联到同一个任务目标。两个近邻无法区分时保持两个目标的占用，重测后再决定拾取。 |
| `observe` 发现批次外目标，下次 `init` 为空 | 新目标仍在列表，参与后续碰撞检查和拾取排序。 |
| 回放 `1bfa8d40` 的最后一次短移受阻 | 拦住原候选路径，保留 `object-005` 和仍有效的精测，从实测车位重规划。只有重新核验通过的路径才下发。 |
| 待拾取列表为空，但复扫能看到盲区目标 | 目标进入规划，任务继续。复扫受阻时能从日志看出未确认的目标或区域与停止原因。 |

日志应能串起每次帧的来源、任务目标 ID 与原始 tracking ID、坐标及误差、关联结果、SDK 请求和响应、实际路径的拦截原因，以及每个目标的拾取结果。
